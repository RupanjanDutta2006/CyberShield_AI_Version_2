## 3. Conflict Resolutions

| Conflict ID | Identified Divergence | Root Cause | Implemented Resolution |
|---|---|---|---|
| **CONF-01** | **Report Schema Divergence** | Member 1 produces deeply nested report with findings/coverage; Member 3 validates 10 top-level fields. | Built `adapter.py` to extract and normalize the 10 canonical fields while keeping Member 1's full report intact in database records. |
| **CONF-02** | **SHA-256 vs Keccak-256** | Member 1 used SHA-256; Member 3 smart contract and TypeScript library used Keccak-256. | Implemented dual-algorithm support: SHA-256 retained for local database verification; Keccak-256 used for on-chain EVM registration. |
| **CONF-03** | **Execution Mode Handling** | Member 1 tests expect simulation mode; Member 3 code threw `ConnectionError` without active node. | Upgraded `service.py` to detect live RPC configuration dynamically: executes real Web3 transactions when configured; falls back to honest `SIMULATED` mode when off-chain. |
| **CONF-04** | **Float Precision Discrepancy** | Python `87.0` vs JS `87` causing hash divergence. | Integrated `normalize_number()` to normalize whole floats to integers while preserving fractional decimals (e.g. `87.5`). |
